## 1. 应聘者入口:选岗位 + 传简历 → 考察大纲(30 秒)

- 打开**演示后台** `http://localhost:5173/admin`,左侧演示:岗位库下拉能看到 5 个岗位(各含自动解析出的考察维度)。
  - 现场可新建岗位:粘贴一段 JD →「创建岗位(自动解析维度)」,展示自动出维度。
- 上传一份应聘者简历(`.pdf/.docx/.txt`),展示自动解析出结构化简历(姓名/教育/经历/技能)。

> **讲点**:JD 不再是人工写题,而是自动拆成**带权重的能力维度**;同一岗位所有面试用同一套考察框架 → 可比。

## 2. 模拟面试:动态追问(2 分钟,核心)

- 从后台「面试列表」打开一场**进行中**面试的链接(如面试 4),或发起一场新模拟面试。
- **现场挑一名评委当"应聘者"**,故意抛一个**泛泛的回答**:
  > 评委答:「我用过 MySQL,做过一些查询优化。」
- 面试官会**基于回答追问细节**(等价例子):
  > 「具体是哪种慢查询?你当时怎么定位、加了什么索引,效果如何?」
- 连续答 2-3 轮,展示**多轮对话 + 维度进度条**在推进。

> **讲点(技术叙事核心)**:市面上的 AI 面试陪练大多是"一次性提问的聊天机器人"。我们是**带状态机的 AI 面试官**——LLM 负责"聪明的判断"(判断回答质量 → 追问/推进),状态机负责"流程的可靠性"(action 枚举校验 + 每维度 ≤3 问、全场 ≤15 问的轮次上限,LLM 出错自动兜底,面试永不崩)。这叫"LLM 做判断,状态机做流程"。

## 3. 个人竞争力报告(1 分钟)

- 面试收尾后,后台面试列表该场状态变「已完成」,总分出现。
- 点「查看报告」,展示:
  - **总分 + 竞争力评价**(与目标岗位的匹配度 + 提升方向);
  - **维度雷达图**(一眼看出强项短板);
  - **维度明细 + 证据引用**:每个维度分数下是应聘者**原话片段**——可复核,不是黑箱打分;
  - **亮点 / 待改进短板 / 提升建议**。
- 现场可直接用**预置的 3 场已完成面试**(82 / 72 / 61 分)快速展示。

> **讲点**:报告 = 标准化 + 证据化。应聘者不用复盘整个面试,只看报告就知道每个维度强在哪、弱在哪、接下来怎么准备。

## 4. 演示后台与横向对比(1 分钟)

- 后台顶栏 →「**横向对比**」`http://localhost:5173/admin/comparison`
- 展示按岗位分组的对比表:同一岗位下多名应聘者,每列一个考察维度,**深色高亮每列最高分**,总分行排序。
- 点某应聘者「报告」可下钻看明细。

> **讲点**:同一岗位、同一套维度、同一张表横向比 —— 帮应聘者了解自己在同类候选人中的位置(演示用;产品主线是个人报告)。

## 5. 三组验收指标(30 秒)

| 指标 | 目标 | 说明 |
|---|---|---|
| 追问触发率 | ≥60% | 回答质量一般时必触发追问,体现"多轮" |
| 评估一致率 | 3 次跑分极差 ≤1 分 | 同一场重复评估 3 次,分数稳定可复现 |
| 单场成本 | <¥1 | 一次完整模拟面试的 DeepSeek 消耗可控 |

## 附:答辩 30 秒技术叙事(11.3)

> "市面上的面试陪练工具大多是'一次性提问 + 题库刷题'。我们做的是**带状态机的 AI 模拟面试官**:先把 JD 拆成能力维度,再逐维度动态追问——LLM 负责判断、状态机负责兜底流程,最后输出带证据引用的个人竞争力报告,告诉应聘者每个维度强在哪、弱在哪、怎么补。让求职者在家就能被真人级面试官练一场。"

## 附:评委可能追问 & 应答要点

- **"LLM 也能干,为什么要状态机?"**
  → 状态机保证**确定性**:轮次上限、维度推进、收尾触发评估都是硬规则;LLM 只是每个回合的"判断器",出错有兜底,面试不会失控。答辩可现场断言:LLM 抽风也只影响单个回合,不影响流程。
- **"证据引用会不会编造?"**
  → 评估 prompt 强制"evidence 必须是对话里真实出现的原话",且逐轮消息留痕可回放复核。
- **"和 offerMaster / DeepInterview 这些陪练工具有什么区别?"**
  → 它们偏"题库刷题 / 一次性问答";我们是**状态机驱动的模拟面试官**:按 JD 拆维度逐维度动态追问,最后给**带证据的个人竞争力报告**,告诉你强项短板和具体怎么补。
- **"为什么用 SQLite 不用 PG?"**
  → MVP 单机演示够用,SQLAlchemy 换连接串即可切 PostgreSQL;答辩口径:"MVP 用 SQLite,生产可切 PG"。
- **"DeepSeek 之外能换吗?"**
  → OpenAI 兼容协议封装,换 base_url + model 即可(通义/智谱/Kimi)。
