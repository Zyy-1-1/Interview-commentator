# 「面评家」现场演示脚本(5 分钟 · 应聘者自助闭环版)

> 产品形态:首页即岗位大厅,应聘者自助完成「传简历 → 看匹配分析 → 选面试官风格 → 数字人语音面试 → 拿竞争力报告」;岗位侧由自助发布 + 官方口令审核治理。
> 前提:`backend/.env` 已配 `DASHSCOPE_API_KEY`(千问)与 `REVIEW_PASSPHRASE`;前后端已启动;Chrome/Edge 打开演示机(需中文 TTS voice,Win11 自带晓晓)。

---

## 〇、演示前准备(3 分钟,可提前做好)

**一键方式(推荐)**:双击项目根目录 `start_all.bat` —— 会先询问是否重置演示数据(回车=重置),然后自动启动后端(:8000)、前端(:5173)并打开浏览器。

手动方式(等价于脚本的三步):

```bash
# 1) 重置演示数据(清空重建:5 岗位 + 20 简历 + 3 已完成 + 2 进行中)
python scripts/make_demo.py

# 2) 启动后端(backend/ 目录,本机 --reload 不可靠需手动重启)
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000

# 3) 启动前端(frontend/ 目录)
npm run dev
```

验证:浏览器打开 `http://localhost:5173` 能看到岗位大厅卡片(含考察维度标签)。

> 应急兜底:若千问网络不可用——大厅、简历上传步骤、已完成面试的报告页仍全程可演示;面试环节改打开「预置进行中」面试的历史消息 + 报告,讲清状态机机制(离线降级时面试官会用兜底问题,恰好展示「不崩」)。

## 1. 岗位大厅:产品从应聘者视角开始(30 秒)

- 打开**首页** `http://localhost:5173`:每个岗位一张卡(职位/公司/JD 摘要/考察维度标签)。
- 一句话带过治理:右上角「发布招聘信息」任何人可提交,「官方审核」口令门控,**审核通过才会上架这个大厅** —— 岗位质量有人把关(细节第 5 步演示)。

> **讲点**:我们不做出题给 HR 用的后台,做应聘者**回家就能练**的模拟面试官。

## 2. 简历分析独立页:先看匹配,再决定面不面(1 分钟)

- 点「开始面试」→ 进入 `/apply/{jobId}` 三步向导。
- 上传一份简历(预置样例:`scripts/演示简历_Python后端_许晨.docx` 或同名 `.md`,md 与 docx 提取内容一致)→ 自动解析出结构化简历卡(教育/经历/技能)。
- 右侧即时出**人岗匹配分析**:总分 + 维度雷达 + 每维度的简历证据 + 亮点/缺口清单。
- 页面底部三位数字人风格卡(陈工/林姐/高老师)→ 选一位 →「开始模拟面试」。

> **讲点**:匹配分析是独立 Agent(简历 × JD 维度),**先给结论再花钱面试**;分析用的证据直接来自简历原文,可复核。

## 3. 数字人语音面试:状态机动态追问(2 分钟,核心)

- 进入 `/interview/{id}`:顶部数字人(风格不同外观不同),面试官**语音读出**题目,口型随 TTS 开合;右上角 🔊 可静音。
- 现场请一名评委当应聘者,**故意抛一个泛泛的回答**:
  > 评委答:「我用过 MySQL,做过一些查询优化。」
- 面试官基于回答**追问细节**(压力面风格会更尖锐):
  > 「具体是哪种慢查询?怎么定位、加了什么索引,效果如何?」
- 连续 2–3 轮,展示:进度条 + 维度 chip + 轮次计数在推进;回答后语音继续。
- 若选了「压力面」,点一句:同一场状态机,换的只是人格语言层。

> **讲点(技术叙事核心)**:市面上的 AI 面试陪练大多是"一次性提问的聊天机器人"。我们是**带状态机的 AI 面试官**——LLM 负责"聪明的判断"(判断回答质量 → 追问/推进),状态机负责"流程的可靠性"(action 枚举校验 + 每维度 ≤3 问、全场 ≤15 问的轮次上限,LLM 出错自动兜底,面试永不崩)。**数字人和语音全部在浏览器端**(SVG + Web Speech API):零服务器成本,无中文语音时自动降级纯文字,体验不中断。

## 4. 个人竞争力报告(1 分钟)

- 面试收尾 → 点「查看我的报告」→ `/admin/reports/{id}`:
  - **总分 + 竞争力评价**(与目标岗位匹配度 + 提升方向);
  - **维度雷达图**(一眼看出强项短板);
  - **维度明细 + 证据引用**:每个分数下面是应聘者**原话片段**——可复核,不是黑箱打分;
  - **亮点 / 待改进短板 / 提升建议**。
- 时间紧可直接打开预置的 3 场已完成面试(82 / 72 / 61 分)。

> **讲点**:报告 = 标准化 + 证据化。应聘者不用复盘整场面试,只看报告就知道每个维度强在哪、弱在哪、接下来怎么准备。

## 5. 岗位供给侧治理:自助发布 + 口令审核(30 秒)

- `/jobs/submit`:现场填一段真实招聘 JD → 提交 → 状态 pending(不会污染大厅,切回首页验证)。
- `/review`:输入口令 → 待审核队列 → 点「通过」→ 回首页,新岗位已上架。
- 口令错误会被 401 拒绝(`hmac.compare_digest` 比对)。

> **讲点**:UGC 岗位 + 官方把关 = 岗位库能长大且不失控。

## 6. 三组验收指标(20 秒)

| 指标 | 目标 | 说明 |
|---|---|---|
| 追问触发率 | ≥60% | 回答质量一般时必触发追问,体现"多轮" |
| 评估一致率 | 3 次跑分极差 ≤1 分 | 同一场重复评估 3 次,分数稳定可复现 |
| 单场成本 | <¥1 | 千问 token 可控;TTS/数字人端侧零成本 |

## 附:答辩 30 秒技术叙事

> "市面上的面试陪练工具大多是'一次性提问 + 题库刷题'。我们做的是**应聘者自助闭环的 AI 模拟面试官**:岗位大厅选岗,先做人岗匹配分析再决定面试;三种人格的数字人面试官用语音出题,背后是**状态机驱动的动态追问**——LLM 做判断、状态机做流程兜底;最后输出带证据引用的个人竞争力报告。语音和数字人全在浏览器端,单场边际成本就是一千问调用。让求职者在家就能被真人级面试官练一场。"

## 附:评委可能追问 & 应答要点

- **"LLM 也能干,为什么要状态机?"**
  → 状态机保证**确定性**:轮次上限、维度推进、收尾触发评估都是硬规则;LLM 只是每个回合的"判断器",出错有兜底,面试不会失控。可现场断言:LLM 抽风也只影响单个回合,不影响流程。
- **"三种面试官风格怎么实现的?会不会影响评估公平性?"**
  → 人格化**只发生在 system prompt 的语言层**(措辞、追问倾向、语气),action 枚举、状态迁移、评估标准与打分 prompt 完全不变——代码里有单测断言三种风格下协议一致。风格解决"练感",标尺解决"公平"。
- **"数字人是视频模型吗?成本高吗?"**
  → 纯前端 SVG 形象 + CSS 动画(眨眼/浮动)+ TTS 事件驱动口型,浏览器完成,零服务器成本;这也是端侧 TTS 的原因:省成本、无排队、断网可演示。
- **"岗位让大家随便传,垃圾信息怎么办?"**
  → 提交 ≠ 上架:pending 状态对大厅不可见,官方口令(`hmac.compare_digest`)审核通过才进大厅,驳回可附原因;审核接口和前端页面都已就位。
- **"证据引用会不会编造?"**
  → 评估 prompt 强制"evidence 必须是对话里真实出现的原话",且逐轮消息留痕可回放复核。
- **"和 offerMaster / DeepInterview 这些陪练工具有什么区别?"**
  → 它们偏"题库刷题 / 一次性问答";我们是**状态机驱动的模拟面试官**:按 JD 拆维度逐维度动态追问 + 人岗匹配前置分析 + **带证据的个人竞争力报告**。
- **"为什么用 SQLite 不用 PG?"**
  → MVP 单机演示够用,SQLAlchemy 换连接串即可切 PostgreSQL;新加的列(岗位 status、面试 style)用启动期幂等 ALTER 迁移,答辩口径:"MVP 用 SQLite + 轻量迁移,生产切 PG 上 Alembic"。
- **"为什么从 DeepSeek 换成千问?换模型麻烦吗?"**
  → OpenAI 兼容协议封装,换 base_url + model 即完成切换(本次改版实测:只改配置引用);国内合规与百炼生态是选型原因。
