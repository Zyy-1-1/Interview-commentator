# 面评家：5 分钟演示与验证边界

本项目面向求职者，流程为岗位大厅 → 简历分析 → 选择面试官 → 多轮问答 → 竞争力报告。现场明确区分实时模型结果、合成演示数据和离线功能测试。

## 演示前准备

- 本地开发使用 README 的前后端启动命令；整站容器入口默认为 http://localhost:8080。
- 实时上传、匹配、审核 JD 和正式模型问答需要可用模型服务及配置。没有配置密钥时可以启动站点、浏览已有数据和运行离线测试，但不能将新简历解析与匹配演示为实时成功。
- 两份合成输入位于 `backend/tests/fixtures/resume_async.md` 和 `resume_database.md`，分别描述异步任务与数据库优化项目。上传这些样例仍会调用真实解析模型，须提前安排实时测试预算。
- `scripts/make_demo.py` 会清空所指向数据库的业务表。只有已确认目标可重置时才运行，优先使用独立临时数据库；不要在含真实简历或已有会话的数据库上直接执行。
- 演示令牌只用于本机合成数据，截图和录屏不展示实际密钥、口令及候选人访问凭证。

## 1. 岗位与简历（1 分钟）

选择一个已上架、具备能力维度的岗位，上传合成简历。说明匹配分析是面试前的模型预估；逐项检查模型是否正确引用材料，不把简历陈述当作已核验能力。

展示换简历重新匹配，确认雷达图跟随新结果。发生模型或网络错误时展示可见错误和重试，不假装已经得到分析结果。

## 2. 简历关联追问（2 分钟）

选择一种面试官风格，先简短介绍经历，再正式回答能力问题。

- 异步任务案例：先回答“我用过 asyncio 做通知任务”，观察面试官是否继续追问并发限制、失败重试或效果度量。
- 数据库案例：回答“我调整过联合索引”，观察是否追问执行计划、索引顺序或优化前后数据。
- 展示维度推进与题目上限；需要纠正流程时，服务端按维度关键词选择有原文锚点的项目。
- 语音由浏览器能力提供，以实际可用的中文语音为准；不可用时使用文字。

这是案例验证，不能从一次展示推导普遍的个性化能力或评分公平性。三种风格共享服务端约束，但可能产生不同追问，需独立对照测量。

## 3. 报告、证据与失败恢复（1.5 分钟）

面试结束后进入“查看报告进度与结果”。生成中自动查询状态，失败后可重试，重复请求复用正在生成的任务或已完成报告。

- 有效评分覆盖不全时不提供完整总分；明确区别“未考察”“证据不足”和有证据支持的低分。
- 查看维度明细，点击消息编号展开原始问答，核对引用来自正确角色和维度。
- 说明原话可定位不等于评分一定合理，也不证明简历事实真实。
- 历史预置报告标注为尚未按新证据规则核验，预置分数不算模型实验结果。

时间不足可展示已完成的合成报告和已有问答。断网应急只回放已有数据；新上传、匹配和新报告不能承诺离线完成。

## 4. 治理与实现（30 秒）

公开提交岗位进入 pending；只有管理员审核分析成功后才上架。候选人私有数据由访问令牌隔离。

技术贡献表述为：用会话快照和服务端状态机约束流程，用简历原文片段连接项目与提问，用消息编号和维度约束评估证据，用后台任务状态处理等待、并发与失败。

## 实验口径

以下是待验证目标，当前离线测试不能证明已达到：

| 项目 | 需要保留的证据 |
| --- | --- |
| 追问质量 | 对答案是否需要补充进行人工标注，分别统计正确追问与无效追问；触发率越高不一定越好 |
| 简历个性化 | 同岗、同模型、相近预算下比较不同简历及无简历输入，记录项目引用是否正确 |
| 评分稳定与合理性 | 对固定输入独立执行多次评估，记录维度分、覆盖率、与人工标注的误差；重复读取缓存不算独立实验 |
| 等待与成本 | 记录各阶段耗时、失败、模型版本及 token，使用实验当日价目计算整场费用 |
| 使用效果 | 获得参与同意后做小规模练习前后对照，说明样本量、任务难度和局限 |

没有核实的竞品概括不用于答辩；不要宣称“真人级”“永不崩”“绝对公平”或未经测量的单场成本。

## 提交前检查

技术说明、测试记录、演示视频和部署命令应对应同一版本。演示视频需要实际录制；真实模型实验和用户试用需另行完成。赛区期限以官方通知为准。
