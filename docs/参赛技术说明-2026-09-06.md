参赛方向：AIC 全球校园人工智能算法精英赛 / 算法创新赛 / 赛题 2：AI+软件创新。赛题依据见 [2026 年官方规则](https://www.aicomp.cn/tracks/tracks-2/3792.html)。赛区提交期限、材料格式和最终提交版本仍需按赛区通知核对。

## 1. 用户问题与核心流程

面向需要练习表达和岗位能力的求职者。项目将岗位要求、简历材料、多轮问答和可复核的练习报告连成一个流程：

岗位大厅（可按类别、学历、薪资、校招/社招、专业与关键词筛选）→ 简历解析与人岗匹配预估 → 选择面试官风格 → 经历暖场 → 按岗位维度提问与追问 → 候选人提问 → 后台评估 → 查看证据和练习建议。另有匿名交流区（发帖、评论、点赞）供应聘者互助。

产品定位为面试训练。匹配预估、模型评分及建议不能直接视为招聘结论。

## 3. 可解释的流程控制

模型负责判断回答及生成问题，服务端约束其输出。开场统一为经历暖场，不当作首项技能已经考察。正式面试按硬技能、软素质、候选人提问、收尾推进；全场题目上限具有最高优先级。

单场规则、岗位大纲和简历背景在创建时进入快照。状态、双方消息在同一事务提交；乐观锁防止并发覆盖，客户端 request_id 用于最近一次请求的重试回放。模型 JSON 类型错误或请求失败有安全兜底，但兜底完成不等于获得高质量面试。

三种风格影响措辞和追问偏好，共享服务端规则。当前没有通过真实实验确认其评分公平性。

## 4. 简历、提问与证据的连接

结构化解析的项目、经历和技能必须能在简历原文中定位，才进入出题背景。保存片段编号、字段路径与字符起止位置，最多 16 段、3500 字符；不主动添加基础身份字段。字符位置按提取后的原文字符串计算，不等同于 PDF 页坐标。

模型可利用这些材料选择提问方向。服务端纠正维度跳转时，根据目标维度关键词选择相关项目；无关联硬技能时使用通用经历问题。原文片段只是候选人的陈述，能力是否成立仍需通过回答核验。

最终报告的计分依据是本场回答：

- 证据必须定位到正确消息编号、候选人角色及目标维度的单条消息。
- 不接受伪造、跨维度、引用面试官或跨消息拼接的原话。
- scored 表示有可定位证据和有效评分；not_assessed 表示未考察；insufficient_evidence 表示尚无有效评分依据。
- 后两类的分数为 null，不按零分惩罚；回答较差可以凭实际原话计低分。
- 全部维度获得有效评分且输入未截断时才给完整总分；否则展示覆盖率和仅代表已评估部分的得分。
- 页面可展开原始问答。出处校验仍不能证明语义相关性、评分正确或简历事实真实。

## 5. 等待与恢复

报告生成不再阻塞收尾响应。任务状态为 not_started、pending、running、ready、failed；查询状态不会触发模型。

数据库原子领取避免同一报告重复评估，任务编号防止旧任务覆盖新结果。后台线程使用独立数据库会话，模型等待不占用数据库事务。进程中断后需等待任务过期并显式重试，当前不是可跨节点持久调度的独立任务队列。

模型默认单次网络超时 45 秒，多次尝试共享 90 秒重试预算；鉴权与参数错误不重试。原默认 25 秒低于实测人岗匹配调用耗时（整份简历 × JD 全维度证据 JSON 约 26 秒），会导致该接口随机超时，已放宽。前端请求超时为 90 秒。网络库的超时不构成严格的进程执行时限。

## 6. 现有验证与待做实验

本轮验证记录见 [分批修复清单](修复清单-2026-09-05.md)。离线测试使用合成输入和模拟模型，验证流程、数据边界、证据规则、事务、并发、恢复与页面行为；这些结果不证明真实模型效果。

后续实验应固定模型与提示词版本，保存数据版本、参数、原始结果和 token：

| 对照 | 主要指标 |
| --- | --- |
| 固定问题 / 基础提示词与当前状态机 | 正确追问、无效追问、维度覆盖、规则违规 |
| 无简历与带简历，同岗不同材料 | 项目引用正确率、追问相关性、幻觉案例 |
| 固定回答独立评估多次，并与人工标注比较 | 维度评分误差、波动、证据相关性、未评分范围 |
| 三种风格、相同素材与相近预算 | 覆盖差异、提问差异、评分差异 |
| 目标用户练习前后 | 完成率、建议可执行性、等难度任务表现和反馈 |

重复请求已有报告只读取缓存，不能证明独立评估一致。费用按实验当日价目和实际 token 计算，不能从离线测试推导单场成本。
