# 2026-09-03 更新清单

本次更新围绕“本地可运行、面试链路可控、候选人访问安全、前后端交付可验证”推进，目标是让项目在不配置真实 `.env` 的情况下完成结构化检查，并为后续接入真实 LLM 和生产部署留下清晰边界。

## 已完成

### 1. 访问控制与数据边界

- 增加管理员审核口令和候选人一次性访问令牌的校验模块。
- 候选人创建接口只返回一次明文 `access_token`，数据库只保存哈希值。
- 候选人列表、详情、匹配、面试、报告等接口按管理员口令或候选人令牌划分访问权限。
- 不再向候选人详情接口返回原始简历文本。
- 公开投递统一进入 `pending`，不能通过请求体参数跳过审核。
- 审核口令改为 `X-Review-Passphrase` 请求头；候选人令牌使用 `X-Candidate-Token` 请求头。

### 2. 面试状态机与并发一致性

- 面试只允许从已审核通过的职位创建。
- 服务端补充硬技能、软技能、候选人问答、结束阶段的顺序约束，避免客户端跳过阶段或提前结束。
- 修正候选人回答与面试官消息的维度归属，候选人问答和结束语不再污染技能评分维度。
- 增加 `request_id` 幂等处理：同一请求重试直接复用结果，复用同一 ID 但内容不同会返回冲突。
- 增加面试版本号和过期更新保护，避免并发请求覆盖面试状态。
- 仅允许已结束面试触发评估，并缓存已生成报告，避免重复调用 LLM。

### 3. LLM、解析与评分稳定性

- LLM 客户端增加明确的缺少 API Key 错误、超时配置、业务层重试边界和不泄露 prompt 的调用日志。
- JD 分析结果统一规范技能类型、顺序、去重、关键词和权重，确保硬技能在前、软技能在后且权重和为 1。
- 匹配评分由服务端重新计算并限制在合法范围，补齐缺失维度，避免信任模型返回的总分。
- 评分质量字段增加 `0-10` 范围裁剪和异常值兜底。

### 4. 简历上传与运行环境

- 上传类型收敛为 `.pdf`、`.docx`、`.txt`、`.md`，增加大小限制、PDF 文件头和 DOCX ZIP 结构校验。
- 上传文件采用分块写入，解析完成后清理临时源文件，不再把临时路径写入候选人记录。
- 增加 Docker 非 root 运行、数据目录、健康检查和后端 `.dockerignore`。
- 修正 Compose 中 SQLite 数据库路径，避免容器重启后使用不一致的相对路径。
- `start_all.bat` 支持定位本机 Miniconda 环境 `interview-commentator`。

### 5. 前端体验与构建体积

- 前端 API 增加超时、JSON 请求头判断、管理员口令和候选人令牌传递。
- 面试重试沿用同一个请求 ID，降低重复提交风险；候选人令牌支持会话存储和 URL fragment 演示入口。
- 修正审核页实际调用审核鉴权接口的问题。
- 限制简历选择类型和大小，补充 ECharts 实例销毁逻辑。
- ECharts 改为按需注册 Radar、Tooltip、Canvas，减少首屏打包体积；移除未使用的 axios 依赖。
- 修正语音事件监听，避免覆盖浏览器全局 `onvoiceschanged`。

### 6. 测试、文档和 CI

- 增加 `pytest.ini`、开发依赖清单和 GitHub Actions：后端测试、前端构建均可自动执行。
- 真实 LLM 测试改为显式 `RUN_LLM_TESTS=1` 且配置 Key 后才运行，默认测试不依赖外部服务。
- 补充上传边界、访问控制、幂等、并发版本、状态机、评分和 JD 规范化测试。
- 更新 README，说明 Miniconda、Docker、鉴权头、演示 token、测试与常用启动命令。

## 兼容性与使用注意

- 应用启动时会对现有 SQLite 数据库补充新字段和索引；不会自动为历史候选人生成访问令牌。旧候选人如需访问受保护接口，需要重新创建/导入候选人，或按项目约定重新生成本地演示数据。
- `skip_review` 已移除；新的公开投递必须等待管理员审核。
- 生产环境应使用独立的管理员口令和 LLM Key，并通过 `backend/.env` 或部署平台注入，不能写入仓库。
- 本次不包含数据库迁移框架替换、生产级用户体系、限流、审计平台和真实浏览器端到端测试，这些属于后续迭代。
